# Code Design

How bcgwcat2 is put together, for anyone (human or AI agent) working on the
code. For installing and using the package, see the [README](README.md).

## Overview

bcgwcat2 is an R package (Province of British Columbia) for working with
groundwater chemistry data from EnMoDS (Environmental Monitoring Data System).
It is a rewrite of [bcgwcat](https://github.com/bcgov/bcgwcat), which used the
older EMS system, and is still in early, experimental development.

All data access goes through the [renmods](https://github.com/bcgov/renmods)
package (installed from GitHub; see `Remotes` in `DESCRIPTION`).

## Development workflow

Run from R in the package root:

```r
devtools::load_all() # load package for interactive work
devtools::document() # regenerate man/ and NAMESPACE from roxygen
devtools::check()
devtools::build_readme() # README.md is generated from README.Rmd
bcgwcat_app() # launch the full Shiny app (port 7405)
test_mod("overview") # launch one Shiny module on its own (internal, R/tests.R)
source("data-raw/parameters.R") # rebuild lookup tables (needs network access)
```

- `NAMESPACE` and `man/` are generated by roxygen, so don't edit them by hand.
- Edit `README.Rmd`, not `README.md`.
- Code is formatted with [Air](https://posit-dev.github.io/air/) (`air.toml`:
  80-character lines, 2-space indent, `<-` assignment). Run `air format .`.
- `RELEASE.R` has the release checklist. `DEVTESTS.R` holds scratch code for
  manual exploration.

**Tests:** run with `devtools::test()`, or run one file with
`devtools::test(filter = "format")`. Tests that read EnMoDS data use the local
renmods cache, so they are skipped on CRAN and CI. The old test suite is in
`NEXT/tests/`, which is excluded from the build and hasn't been ported yet.

## Data pipeline

The core of the package doesn't depend on Shiny. Data flows through these steps:

1. **`fetch_renmods()`** (`R/fetch.R`) connects through
   `renmods::renmods_connect()`, filters by `Location_ID` (EMS IDs, always
   converted to character) and by date range, then loads the result into memory.
   It returns the raw EnMoDS columns, which have TitleCase names.
2. **`fmt_minimal()`** (`R/format.R`) is the central formatter, and almost
   everything downstream expects its output. It selects columns, converts names
   to lower case and keeps only known parameters. It then runs `add_obs_wells()`
   → `add_bcgwcat_params()` → `add_meq()` → `add_placeholder()` →
   `add_charge_balance()` → `add_water_type()`.
   - The output is in **long** format: one row per location, date and parameter.
   - Derived values are added as extra rows. These include meq values
     (`result_unit == "meq/l"`), charge balance and anion/cation sums.
3. **`fmt_wide()`** pivots the output of `fmt_minimal()` to wide format. Before
   pivoting, it resolves repeated and multi-method measurements with
   `fix_multiple_measures()` (`R/fix.R`).
4. **Calculations and outputs**:
   - `meq()`, `charge_balance()` and `water_type()` are in `R/calculations.R`.
   - Comparison with water quality guidelines is in `R/water_quality.R`.
   - `stiff_plot()` is in `R/plots.R`.
   - The reactable tables are in `R/tables.R`.

`check_samples()` (`R/checks.R`) validates inputs. If it receives raw output
from `fetch_renmods()`, it applies `fmt_minimal()` automatically.

## Data assumptions

- A sample is considered an observation with a unique `Location_ID`,
  `Observed_Date_Time`, `Observed_Parameter_ID`, `QC_Type`, and (possibly)
  `Data_Classification`

## Parameter and metadata lookup tables

CSV lookup tables in `inst/extdata/` control how parameters and columns are
named. They are read at runtime by `read_data()` (`R/utils-data.R`) and exposed
through `index_params()`, `index_meta()`, `index_meta_params()`, `ion_details()`
and `wq_std()`.

- `index_params()` maps EnMoDS parameter names (`enmods_param`) to snake_case
  `bcgwcat_param` names. The code uses `bcgwcat_param` names throughout.
- `index_meta()` and `index_meta_params()` map column names between EnMoDS and
  bcgwcat.
- `meta_vars(which, param_vars)` returns the set of columns for `"bcgwcat"` or
  `"enmods"`. These columns are also the keys that identify a single
  observation.
- EnMoDS reports its own charge balance and ion sums. Those parameters get an
  `_enmods` suffix, so they don't clash with the `charge_balance`, `anion_sum`
  and `cation_sum` that this package calculates.

**These CSVs are generated files.** `data-raw/parameters.R` builds them from:

- the hand-edited CSVs in `data-raw/`
- the `ion_details` table, which is defined inside the script
- the drinking water guidelines (`wq_std`), which are downloaded with `bcdata`

To change a table, edit the source in `data-raw/` and re-run the script. Don't
edit `inst/extdata/` directly. The script also writes the internal objects
`ems_ids_all` and `min_date` to `R/sysdata.rda`.

## Shiny app

`bcgwcat_app()` (`R/app.R`) builds a `bslib::page_navbar` from modules in
`R/mod_*.R`. Each module has a `mod_<name>_ui()` and a `mod_<name>_server()`
function.

- **Overview:** `mod_overview_server()` handles the status and downloads of the
  renmods cache. It returns `updated`, a reactiveVal counter that goes up each
  time the local data changes.
- **Data:** `mod_data_server(updated, ...)` takes that counter and handles
  choosing EMS IDs and dates and fetching the data.
- **Water quality and plots:** the data module returns the sample data that
  `mod_water_quality_server()` and `mod_plots_server()` use.
- **Messages:** the package's `inform()` and `abort()` (cli wrappers in
  `R/messages.R`) are shown in the in-app console through `with_messages()`
  (`R/utils-shiny.R`).
- **Theme:** the theme comes from `inst/shiny-assets/_brand.yml`, and the BC
  Sans fonts are bundled.
- **Prompts:** `bcgwcat_ui()` sets `rlang_interactive = FALSE`, so renmods
  doesn't stop to ask questions in the terminal.

## Conventions

- In dplyr code, use the `.data$` and `.env$` pronouns.
- Namespace-qualify function calls (`dplyr::`, `tidyr::`, ...). The exceptions
  are `shiny` and `bslib`, which are imported whole, and `glue`.
- Use the package's own `inform()` and `abort()` for messages and errors.
- New R files start with the Province of BC Apache 2.0 copyright header.
